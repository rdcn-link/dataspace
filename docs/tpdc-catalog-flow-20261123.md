# TPDC catalog and exploration flow (2026-11-23)

The old4fair-web center page reads executable center configuration, while the Conet catalog lacked the exact two versions. Direct submission therefore did not prove the catalog-button flow. At user request, CMFD v2.0(1951-2024) and global solar radiation(1983-2018) were registered in the production catalog with original external IDs and center mappings. No CSTR/DOI/license was invented, and physical paths were not copied into public metadata. Initial registration did not overwrite older records. The user subsequently requested retaining only these two center-owned records; production was already in that state when checked, so0additional documents were deleted. Other centers, statistics, tasks and artifacts were untouched.

Flow: verify current-session UID, issue its OIDC token, resolve authoritative center mapping, submit server-side and return an allowlisted token-bearing exploration URL. Browser input is metadataId only. findbyopenid belongs to WeChat identity linkage; an already-verified backend UID does not require repeating it for every submission. A single visible gateway request still performs token issuance and center submission internally.

The UI stores short-lived pending metadata IDs, never tokens. It resumes after login, offers an explicit continue button if popups are blocked, discards expired intents and reauthenticates on401. ScienceDB eligibility and center-origin allowlists remain unchanged.

Controlled integration used a verified account and an in-memory short-lived session proof; it does not claim a fresh QR login. Login-resume/popup behavior has separate tests. All32related tests passed and the real public center-filtered page showed exactly two cards. No scientific analyses or artificial statistics were created. Static files were backed up with hash guards and deployed without service restart. Local source copies are synchronized without automatic Git commit/push.
