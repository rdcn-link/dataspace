# 应用创作与版本控制

复用 `conet.applications` 和不可覆盖的 `application_versions` 集合。草稿仅创建者和平台管理员可见，二者均可编辑从未发布的草稿。应用一经发布，内容永久锁定，下线后仍不可修改；调整时创建新应用或复制草稿。上下线不改写科学分析历史、产品和审批。

认证接口前缀为 `/api/metadata/platform`：

| 接口 | 用途 |
| --- | --- |
| `POST /application-drafts` | 保存应用、流程 YAML 和预期版本 |
| `GET /applications/:id/authoring` | 定义、版本和服务端操作权限 |
| `POST /applications/:id/copy` | 创建独立归属的草稿 |
| `GET /applications/:id/package` | 导出 `.conetapp.zip` |
| `POST /application-packages/import` | 导入为新的私有草稿 |
| `POST /applications` | 校验并一次性发布 |
| `POST /applications/:id/discard` | 按预期版本移除草稿 |

并发版本冲突返回409，修改已发布内容返回403。草稿列表和版本接口执行相同可见性校验。旧 App Builder 保存、程序包入口也转入相同规则。复制不继承数据授权、任务历史、验证状态和成果。发布复用既有运行时编译，不提交科学计算。

应用适配器可提供 `registryAdapter.authoringTemplate()`，返回 `{job,evidence}`。科学文件适配器复用执行脚本中的“read_item → 配置的分析算子”流程，数据地址、文件名由运行时输入提供，方法默认值可配置。其他平台应用优先利用已有平台流程证据。尚无真实流程的设计保留为空草稿，同时携带输入要求及参数说明，不编造可执行流程。节点放置、嵌入的私有配置及固定实体路径改为必填运行时输入。

程序包格式为 `conet-application` 第2版，包含 `manifest.json`、`application.yaml`、`job.yaml`，可携带已上传的 PNG/JPG 封面和背景；第1版定义也可以导入为新草稿。包最大4MiB，单份定义或清单最大256KiB，单张图片最大2MiB。解压前校验中央目录范围、重复文件、路径及展开大小，并拒绝凭据。程序包不包含实体数据、代码、令牌、任务成果或访问审批。内置资源和HTTPS图片保留引用；上传图片随包携带，导入时复用图片上传接口重新校验。

网页网关提供 `/api/appbuilder/designer/`，代理当前真实 XStream Designer，仅开放定义编辑、算子元数据和导出，拒绝推断、预览和计算。该创作入口提供的设计器脚本关闭自动推断，并关闭大模型对话配置；检查上游脚本标记，不兼容版本明确拒绝。窗口回传核对来源域、窗口、随机通道及应用切换代次。已有独立 Designer 部署不变，其访问继续遵守自身部署控制。

目录服务通过 `CONET_SERVER_URL` 连接核心服务。访问配置可设置 `designerBackendURL`（正式环境为 `http://127.0.0.1:28840/`），让服务端设计器请求不绕经公网登录入口，也不转发浏览器凭据。首次节点、任务索引刷新在后台进行，远端元数据连接就绪前仍可访问MongoDB中已有记录。发布与后台刷新对同一应用、版本共用编译中的请求；完全相同的发布重试不修改内容，修改已发布定义则拒绝。

浏览器将修改后的 Job YAML 回传到草稿，再由用户明确保存。新增变量绑定和科学成果解码需在发布前配置。流程结构校验通过、或复制已验证应用，均不等于新应用通过科学验证。用户贡献应用的计算审批尚未通用化，本改动不开放新科学运行，不绕过数据中心审批。输出二进制的算子仍需配置对应结果处理，通用JSON结果声明不能冒充已验证的二进制成果展示器。

测试：`node --test application-authoring.test.mjs`。端到端覆盖NPP复制、编辑、回传、保存、刷新，程序包导入导出，匿名隔离，并发版本冲突和发布后不可覆盖，不启动科学计算。部署需保留环境端口差异（测试8870，当前正式总节点28870），备份原文件，安装前核对原文件SHA-256。
