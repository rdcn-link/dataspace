# 数据智能机器人工作台

第一版部署于 10.0.90.48，访问 http://10.0.90.48:9590/ 。这是规则和模板驱动的业务原型，未连接大模型，不要求实体数据。所有无证据事项标记待补充或待核实。

## 业务定位

机器人是中心工作人员的专业业务助手，负责把需求组织成检查、方案、交付材料和复核任务。它与 DACP 的关系是：机器人组织业务，DACP 提供数据访问和任务执行基础，XStream 与算子完成实际处理。第一版仅巡检机器人调用本机 DACP 看板；其他机器人没有向 DACP 提交执行或修改生产数据。

| 机器人 | 第一版业务行为 | 交付物 |
|---|---|---|
| 质量评估 | 检查声明材料；对 CSV 样本实际计算行数、空值、重复与列数一致性 | 样本质量结果、整改清单、报告 |
| FAIR 评测 | 按 15 条原则逐项列证据，区分声明和待补项 | FAIR 证据矩阵、改进建议 |
| 元数据整理 | 保留已有事实，缺失项为空，生成 Dataset 描述草案 | 元数据 JSON、补录事项 |
| 分类分级 | 在描述及样本表头发现需复核关键词 | 线索清单、访问控制建议 |
| 权属与授权核查 | 整理来源、权利主体、许可及成果权益问题 | 权利核查与授权草案 |
| 数据接入 | 起草私有发布的目录接入配置 | DACP 配置草案、接入验收清单 |
| 数据服务开发 | 分解需求，设计参数、输出、流程和测试条件 | 服务契约、Job 设计草案 |
| 数据产品开发 | 组织用户、价值、交付包、权益及发布门槛 | 产品说明书、发布评审材料 |
| 需求与资源匹配 | 把需求转为资源条件和待验证缺口 | 资源需求与匹配验证方案 |
| 数据加工方案 | 规划清洗、转换、聚合及回退 | 加工方案、校验规则 |
| 溯源与成果登记 | 组织来源、执行版本、成果权益记录结构 | 溯源及登记草案 |
| 服务运行巡检 | 实际请求固定本机 DACP 看板，记录状态和时间 | 端点巡检报告 |

FAIR 检查参考 [FAIR Guiding Principles](https://www.gofair.foundation/fair-principles)。第一版只做材料自查，不自动验证标识符解析、协议访问、词表或标准符合性，不给出认证分数。样本质量结果只适用于上传的样本。

## 用户流程

1. 选择机器人、中心和模式。业务设计无需实体文件；样本验证要求提供 CSV。
2. 填写业务目标和已知材料；未知内容可留空。可填入明确标注的合成示例。
3. 创建任务，后台实际运行规则与草案生成器；保存输入、事件及交付文件。
4. 查看证据与报告，下载 JSON 或 Markdown。
5. 记录草案复核通过或退回意见。退回后可基于原输入新建版本，保留原始记录。

状态包括排队、处理中、待复核、已复核、退回完善、失败、中断。服务重启时未完成任务标记为中断；已完成任务和复核记录持久保存。

## 中心部署模型

90.48 是当前唯一实际运行工作台的中心。中心部署页允许登记其他中心计划，未部署中心不能运行任务；登记不表示远程安装成功。可在各中心部署同一程序并分别设置状态目录。正式联合调度、中心身份认证及跨中心结果交换尚未接入。

本原型的复核人由用户自行填写，不是身份验证后的管理员审批。正式执行仍需各参与中心管理员批准，并事先约定成果权益。草案不自动发布、不自动运行任意代码、不自动接入生产数据库，不估算收入或虚构成效。

## 运维与后续扩展

- 部署目录：`/mnt/data/conet/data-robots`；端口 9590，绑定内网 IP。
- 服务：`data-robots.service`，开机自启。
- 状态：`state/workbench.json`，原子写入，目录权限 700、文件 600。当前为单进程、小规模原型。
- 运维：`sudo systemctl status data-robots`、`sudo systemctl restart data-robots`、`sudo journalctl -u data-robots -n 100 --no-pager`。
- 停用：`sudo systemctl disable --now data-robots`，保留数据。首页入口可从备份恢复。
- 本地运行：Node.js 20 以上，`npm start`；验证：`npm test`。无第三方运行依赖。
- 线上端到端证据：`deployment-verification.json`，覆盖 12 类机器人和交付下载。初始示例任务均标注“合成演示”。
- 工作台为内网共享原型，没有用户隔离；只使用获准的非敏感业务材料或合成样本。
- 后续应依次接入中心身份和正式审批、真实元数据/存储适配、版本化算子及执行证据、专业规则，再接入受控的大模型规划能力。大模型输出不能直接绕过规则、权限和人工确认。

扩展机器人在 `catalog.mjs` 声明业务，在 `engine.mjs` 实现检查与交付逻辑；界面和任务存储自动复用。`server.mjs` 提供同源写入检查、输入大小限制、任务与成果接口。此处的服务和 Job 输出均为设计契约，不是已发布服务或可直接提交的科学 Job。

## 用户中心整合（2026-11-18）

工作台已从科诺空间主导航移入用户中心，仅经过 OIDC 实时身份核实的管理员可访问页面、接口及成果下载。线上服务绑定127.0.0.1:9590，经科诺空间会话网关访问，不再直接开放9590。配置 `CONET_REGISTRY_MONGO_URI` 和 `CONET_MONGO_DRIVER` 后，业务状态写入 `conet.robot_runs/robot_centers/robot_settings`；既有文件首次导入且保留历史成果与复核。新任务及复核记录可信管理员身份，历史自行填写身份不重新标记为可信。未配置MongoDB时仍支持原文件模式用于本地测试。规则/模板草案边界不变，见[用户中心说明](../user-center/README_zh.md)。
